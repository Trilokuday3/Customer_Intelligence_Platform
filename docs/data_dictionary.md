# Data Dictionary

Source of truth for shapes/types is `src/data/schemas.py` (pydantic
models) — this doc explains what each field *means*; the schema file
enforces it. Generated by `src/data/generator.py`, config in
`src/data/config.py`. See `docs/target_definition.md` for the churn/CLV
point-in-time design these tables are built around.

## customers

Grain: one row per customer.

| Column | Type | Meaning |
|---|---|---|
| `customer_id` | string, PK | Synthetic identifier, `C000000`-style |
| `signup_date` | date | First-touch/account-creation date |
| `country` | string | ISO-ish country code (6-country catalog) |
| `acquisition_channel` | enum | `organic`, `paid_search`, `social`, `affiliate`, `email`, `referral` |
| `plan` | enum | Loyalty tier `bronze`/`silver`/`gold`, assigned from the customer's latent activity level (not a feature you'd know at signup in a real system — treat as descriptive, not predictive, until re-derived per-cutoff) |

## products

Grain: one row per product.

| Column | Type | Meaning |
|---|---|---|
| `product_id` | string, PK | `P00000`-style |
| `category` | string | One of 8 catalog categories |
| `price` | float | List unit price (log-normal distributed, a few premium items pull the tail) |

## orders

Grain: one row per order (single product line — no multi-line baskets in v1).

| Column | Type | Meaning |
|---|---|---|
| `order_id` | string, PK | `O00000000`-style |
| `customer_id` | string, FK -> customers | |
| `order_date` | datetime | |
| `product_id` | string, FK -> products | |
| `quantity` | int | > 0 |
| `amount` | float | `unit_price * quantity * (1 - discount)`, already net of discount |
| `discount` | float | 0–1, one of `{0, 0.1, 0.2}` (0 most common) |
| `status` | enum | `completed`, `refunded` (~4%), `cancelled` (~2%) |

**Qualifying order** (used for churn/CLV/RFM) = `status == "completed"`.
Refunded/cancelled orders exist in the table but are excluded from value
and activity calculations.

## interactions

Grain: one row per engagement event (login/browse/cart/email).

| Column | Type | Meaning |
|---|---|---|
| `interaction_id` | string, PK | `I00000000`-style |
| `customer_id` | string, FK -> customers | |
| `event_time` | datetime | |
| `event_type` | enum | `login`, `page_view`, `add_to_cart`, `email_open`, `email_click` |
| `channel` | enum | `web`, `mobile_app`, `email` |

Fires roughly 6x more often than orders per active customer — behavioral
engagement signal is meant to move (and decay before churn) faster than
transaction signal.

## support

Grain: one row per support ticket.

| Column | Type | Meaning |
|---|---|---|
| `ticket_id` | string, PK | `T0000000`-style |
| `customer_id` | string, FK -> customers | |
| `created_at` | datetime | |
| `category` | enum | `billing`, `shipping`, `product_issue`, `cancellation_request`, `general` |

Ticket rate scales with a per-customer "support friction" latent
variable; customers who go on to churn skew toward
`cancellation_request`-flavored tickets in the run-up.

## predictions (schema only — populated starting Phase 5/6)

Grain: one row per (customer, model_version, prediction_date).

| Column | Type | Meaning |
|---|---|---|
| `customer_id` | string, FK -> customers | |
| `model_version` | string | e.g. `churn-xgb-v1` |
| `churn_probability` | float | 0–1 |
| `predicted_clv` | float | >= 0, net revenue over the CLV horizon |
| `prediction_date` | date | The cutoff the prediction was made as of |

## Table grain summary

| Table | Grain | Approx. rows @ 8,000 customers |
|---|---|---|
| customers | 1 / customer | 8,000 |
| products | 1 / product | 80 |
| orders | 1 / order | ~155,000 (~19/customer) |
| interactions | 1 / event | ~916,000 (~115/customer) |
| support | 1 / ticket | ~13,000 (~1.6/customer) |
| predictions | 1 / customer / model_version / prediction_date | 0 until Phase 5+ |
